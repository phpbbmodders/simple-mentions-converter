# Verification

Checks performed during the 10/27/2026 development session:

- PHP 8.4.27 CLI.
- phpBB `4.0.0-a3-dev`, source commit
  `a1ccfe6258dfe3223e908da23e26dccca3ec5cac`.
- Disposable SQLite board installed and seeded using the committed seed-forum
  runner and standard fixture script.
- Separate disposable MariaDB 11.8.2 / InnoDB board installed using phpBB's CLI
  installer and seeded using the same committed standard fixture helper.
- Legacy XML generated by s9e using the exact BBCode definitions from Simple
  Mentions 1.0.5 and 2.0.0. The leftover definition was stored in the real
  `bbcodes` table and the conflicting formatter cached before conversion.
  The original extension was not installed/enabled as part of these tests;
  this models the already-disabled/data-deleted upgrade state in the report.

## Automated checks

`php tests/converter.php`: **40 checks passed**, including:

- Old username-only mentions, user/group IDs, XML entities, Unicode, and an
  earlier username label preserved alongside its numeric user ID.
- Recovery of user/group IDs from native mention delimiters swallowed by the
  legacy definition.
- Missing targets converted to plain text, with unresolved counts.
- Already-native tags and literal CODE examples unchanged.
- Other formatting and quote attributes retained.
- Malformed XML, entity declarations, unknown attributes, mismatching IDs,
  nested formatting, and old non-XML stored mentions rejected.
- Exact known BBCode definitions distinguished from customized definitions.
- Idempotent conversion.

`python3 tests/integration.py --board ...`: **passed on SQLite**, checking:

- Dry-run identifies 16 affected fields and preserves application data.
- Online board, active mentions extension, unknown BBCode definition, malformed
  content, unsafe recovery location, and concurrent converter rejected.
- Injected SQL failure on the second row rolls back the first update in the
  same batch as well.
- Deliberate one-batch stop returns `2`; the legacy BBCode stays installed.
- Resume completes, including private messages and composite-key poll options.
- Recovery JSON contains original/replacement data and the legacy BBCode;
  recovery files have private permissions.
- No historical notification rows created.
- Follow-up dry-run reports zero remaining changes; completed rerun changes no
  application data.
- Native core rendering, edit/unparse/reparse, quoted content, group IDs,
  literal CODE, and new-mention ID extraction pass.
- Normal `submit_post()` creates an actual `notification.type.mention` row for
  another fixture account.

On **MariaDB/InnoDB**, the fixture helper and real converter also passed dry-run,
one-batch interruption, resume, cleanup, clean follow-up scan, native rendering,
editing/reparse, and normal-post notification creation. Temporarily converting a
test table to MyISAM caused apply to reject it before content writes; the test
table was then returned to InnoDB.

`tests/browser.js` using Playwright against the SQLite board: **passed** login,
converted-post rendering and profile link, edit form BBCode, quote form content,
and a 390 × 844 viewport. No post was submitted by the browser check.

PHP syntax checks passed for every PHP file; JavaScript syntax and Python
compilation checks passed. CLI no-argument help and unknown-option rejection
were exercised.

## Limits

These tests use synthetic fixtures, not the support poster's database or a
full production upgrade history. Username reuse/renames, customized BBCode,
third-party content tables, and other board-specific modifications still need
review on a copy of the actual board.

PostgreSQL uses the same DBAL paths and is accepted by the tool, but was not
runtime-tested here. MySQL was not tested separately from MariaDB. Windows and
macOS were not tested. Future phpBB 4.0 changes may require adjustments; the
version check and native parser probe do not constitute a guarantee for every
future 4.0 build.
